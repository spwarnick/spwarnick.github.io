Overview

Lab Overview

This module established the foundational lab environment for the Cybersecurity Operations course — a segmented virtual network built around pfSense as the central firewall/router, with Kali Linux on the WAN side and Ubuntu machines on the DMZ and LAN segments. The primary objective was to generate, capture, and analyze network traffic across five protocols: host/service discovery via Nmap, SSH, FTP, DNS, and HTTP. Each traffic type was captured as a pcap file using Wireshark and is available for download below.

SSL Key Log File

The DNS lab generated a sslkeys.log file via the SSLKEYLOGFILE environment variable. This file can be loaded into Wireshark (Preferences → Protocols → TLS → Pre-Master-Secret log) to decrypt the DoH HTTPS traffic in dns.pcap and inspect the underlying DNS queries in plaintext.

Module 1

Host & Service Discovery

The reconnaissance module used Nmap to perform host discovery and service enumeration against the Ubuntu DMZ machine. Three scan types were executed — ICMP ping, SYN ping, and a full port/version/OS detection scan — with all traffic captured in Wireshark.

Nmap Scan Progression

Scan Commands

Port scan — identify open ports on Ubuntu DMZ sudo nmap -PS 192.168.20.10 # 4. Full OS + version + service detection scan sudo nmap -Pn -sS -sV -O 192.168.20.10 -oN scan_results.txt

Notable — OS Detection

The -O flag enabled Nmap's OS fingerprinting via TCP/IP stack analysis. The scan correctly identified the Ubuntu DMZ as a Linux host, demonstrating how OS detection works passively from packet-level behavioral differences between operating system implementations.

Findings

Key Findings

Finding 1 — FTP Transmits Credentials in Plaintext

The ftp.pcap capture clearly shows the FTP username and password transmitted in plaintext — visible to any observer with network access. The Hydra brute-force succeeded in under a second against a 6-entry wordlist. This is why FTP has been superseded by SFTP and FTPS in modern environments, which encrypt the control channel.

Finding 2 — SSH Provides No Useful Payload Visibility

In contrast to FTP, the ssh.pcap shows only encrypted TLS records — the remote commands executed, the file created, and its contents are completely invisible to a passive observer. This is the fundamental security advantage of SSH over legacy protocols like Telnet and FTP.

Finding 3 — DNS-over-HTTPS Hides Queries from Passive Inspection

Standard DNS queries appear in plaintext in packet captures. The DoH query to 1.1.1.1 appeared as encrypted HTTPS traffic — indistinguishable from normal web browsing. However, the SSLKEYLOGFILE technique demonstrated that TLS session keys captured at query time can decrypt the traffic post-capture in Wireshark, a technique used by security analysts to inspect encrypted traffic in controlled environments.

Finding 4 — Nmap OS & Version Detection Is Highly Accurate

The -sV -O scan correctly identified all six running services with version numbers and the underlying OS. This level of detail from a single unauthenticated scan illustrates why service version disclosure (via banners and TCP/IP stack fingerprinting) is a significant reconnaissance risk that defenders should mitigate through banner suppression and firewall rules.

Takeaways

Lessons & Takeaways

This module built the practical foundation for the rest of the Cybersecurity Operations course — a working segmented lab environment with real traffic flowing between network zones. The pcap files generated here serve as baseline "known-good" captures that subsequent analysis modules can reference when identifying anomalous traffic.

The most valuable insight across all five captures is the stark contrast between encrypted and unencrypted protocols. SSH and DoH produced opaque captures; FTP and HTTP produced fully readable ones including credentials and file contents. This contrast makes a compelling case for encrypting all network services by default — a principle that underpins modern Zero Trust architecture.
