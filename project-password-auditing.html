Overview

Lab Overview

This two-part lab explored password auditing and offline password cracking techniques against both Windows and Linux operating systems. Using Kali Linux as the attack platform and John the Ripper (JtR) as the primary cracking tool, the exercises demonstrated how weak passwords can be compromised through dictionary attacks and brute-force attacks — even when those passwords are stored as cryptographic hashes.

The lab was designed to build foundational knowledge in credential security, hash analysis, and offensive auditing techniques — skills directly applicable to penetration testing and security assessments.

W

Windows Lab

Target: Windows 10 VM

  • Extracted NTLM hashes from SAM hive using creddump7
  • Generated custom wordlist with crunch
  • Cracked hashes via dictionary attack
  • Performed targeted brute-force with digit constraints
L

Linux Lab

Target: Ubuntu VM

  • Located SHA-512 hashes in /etc/shadow
  • Used unshadow to combine passwd + shadow
  • Cracked hashes via wordlist attack
  • Configured JtR incremental mode for brute-force

Methodology

Methodology

Environment Setup

Both labs used a VirtualBox environment with three VMs: a Kali Linux attack machine, a Windows 10 target, and an Ubuntu target. Each target VM was powered off and its virtual hard disk was attached directly to the Kali VM, simulating physical access to a machine — a common scenario in forensic investigations and physical penetration tests.

Windows — Hash Extraction

After mounting the Windows 10 virtual disk, the creddump7 toolkit was used to extract password hashes from the Windows SAM (Security Account Manager) database. The pwdump.py utility reads the SYSTEM hive to decrypt the SAM hive and outputs NTLM hashes.

Windows — Hash Dump

# Mount the Windows disk partition sudo mount /dev/sdb1 /mnt/windows # Navigate to the Windows config directory cd /mnt/windows/Windows/System32/config # Extract NTLM hashes using creddump7 python2.7 ./pwdump.py /mnt/windows/Windows/System32/config/SYSTEM \ /mnt/windows/Windows/System32/config/SAM > ~/Desktop/samdump.txt # Generate a 4-digit numeric wordlist using crunch crunch 4 4 0123456789 > ~/Desktop/4digits.txt

Linux — Hash Extraction

On Ubuntu, user credentials are split across two files: /etc/passwd (usernames and account info) and /etc/shadow (hashed passwords). The unshadow utility merges these files into a single format that John the Ripper can process.

Linux — Hash Extraction

# Mount the Ubuntu disk partition sudo mount /dev/sdb1 /mnt/ubuntu # Navigate to the etc directory on the mounted disk cd /mnt/ubuntu/etc # Combine passwd and shadow files for JtR sudo unshadow passwd shadow > ~/Desktop/unshadowed.txt

Dictionary Attack

For the first attack phase on both systems, John the Ripper was run with a wordlist targeting the first-name user account. The password (1000) was known to be weak and was added to JtR's default password.lst for the Linux lab; for Windows, a complete 4-digit numeric wordlist was generated with crunch.

Dictionary Attack — Linux

sudo john --wordlist=password.lst --users=spencer ~/Desktop/unshadowed.txt sudo john --show ~/Desktop/unshadowed.txt

Dictionary Attack — Windows

sudo john ~/Desktop/samdump.txt \ -wordlist=/home/kali/Desktop/4digits.txt \ --format=NT -user=spencer

Brute-Force Attack

The second attack phase targeted the last-name account using JtR's incremental (brute-force) mode. To make the attack feasible, the john.conf configuration file was modified to constrain the search space to 4-digit numeric passwords only.

Brute-Force — john.conf modification

# Modified section in john.conf [Incremental:Digits] File = $JOHN/digits.chr MinLen = 4 MaxLen = 4 CharCount = 10 # Run brute-force attack sudo john --incremental=Digits --users=warnick ~/Desktop/unshadowed.txt

Findings

Key Findings

Finding 1 — Password Storage Locations

On Linux, usernames are stored in /etc/passwd and hashed passwords in /etc/shadow. On Windows, hashes are stored in the SAM (Security Account Manager) database, encrypted with a key stored in the SYSTEM hive.

Finding 2 — Hashing Algorithms

Ubuntu uses SHA-512 for password hashing, identifiable by the $6$ prefix in the hash string. Windows uses NTLM (NT LAN Manager) hashing, which is an unsalted MD4 hash — significantly weaker than SHA-512.

Finding 3 — Weak Passwords Are Trivially Cracked

A 4-digit numeric password (1000) was cracked near-instantly via dictionary attack on both platforms. Even without the password in the wordlist, a constrained brute-force attack with a known character set and length cracked it in seconds — demonstrating that short numeric passwords provide virtually no security.

Finding 4 — Physical Access Bypasses OS Authentication

By mounting the target VM's virtual disk directly on Kali Linux, all OS-level access controls were completely bypassed. This underscores the importance of full-disk encryption (e.g., BitLocker, LUKS) as a defense against physical or offline attacks.

Takeaways

Lessons & Takeaways

This lab reinforced how quickly weak passwords can be compromised when an attacker has offline access to credential hashes. The practical experience of extracting, cracking, and analyzing hashes across two operating systems built a solid foundation for understanding both offensive techniques and the defensive controls that counter them.

Key defensive recommendations that emerged from this exercise: enforce strong password policies (length, complexity, no purely numeric passwords), implement full-disk encryption to prevent offline hash extraction, and use modern hashing algorithms with salt (e.g., bcrypt, Argon2) rather than fast unsalted hashes like NTLM.
